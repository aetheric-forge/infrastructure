# Aetheric Forge Infrastructure v2.0.0

## Overview

v2.0.0 establishes Civo Kubernetes as the reference cloud deployment for the
Aetheric Forge development platform. It brings the platform's private network,
internal DNS, certificate authority, ingress, identity, data services, and
GitOps bootstrap together as one operational environment.

This is a major release because it changes both the deployment architecture and
the ownership model of several Kubernetes resources. Existing installations
should follow the [v2 Upgrade Runbook](../upgrade-runbook.md) rather than
treating this as a routine manifest update.

## Platform included in this release

The development environment currently includes:

- A Pulumi-managed Civo private network, managed k3s cluster, node pool,
  firewalls, and WireGuard gateway
- Public and private ingress-nginx controllers backed by Civo load balancers
- Argo CD for GitOps reconciliation
- ExternalDNS using Cloudflare for public records and RFC2136/BIND for the
  internal zone
- step-ca and cert-manager for private ACME certificate issuance and renewal
- Keycloak as the platform identity provider
- MinIO with OIDC login and group-based administrative access
- RabbitMQ, CloudNativePG/PostgreSQL, MongoDB, Redis, and Velero
- A Docker Compose development stack for running shared services locally

## Highlights

### Civo deployment support

- Added a complete Civo development overlay for platform controllers,
  configuration, operators, and services.
- Added Pulumi provisioning for the Civo network, managed Kubernetes cluster,
  node pool, firewall rules, load balancers, and WireGuard gateway.
- Added kubeconfig merging and generated Pulumi environment output for the Civo
  workflow.
- Added a Civo-specific WireGuard setup path and per-node routing for the home
  network reached through the gateway.

### Private ingress and service DNS

- Separated public and private ingress-nginx controllers.
- Added discovery of Civo load balancers' private addresses instead of
  publishing the public addresses reported in Kubernetes Service status.
- Added two-pass publication for RabbitMQ, MongoDB, and PostgreSQL so
  ExternalDNS does not publish incomplete or incorrect service targets.
- Added the internal S3 endpoint through the private ingress controller.
- Added a managed CoreDNS custom zone that forwards internal lookups to the
  home resolver.

### Internal PKI and ACME reliability

- Configured cert-manager DNS-01 self-checks to query the authoritative BIND
  listener directly, avoiding stale negative answers in the Pi-hole resolver.
- Added the gateway source NAT required for Kubernetes pod traffic to reach the
  home DNS network and receive replies.
- Restored automatic private certificate issuance and renewal for Argo CD,
  MinIO, and RabbitMQ.

### Identity and service access

- Added public Keycloak ingress for the development identity provider.
- Updated Argo CD and MinIO ingress and OIDC configuration for the Civo-hosted
  environment.
- Added the `minio-admins` policy and group mapping used for MinIO
  administrative access through SSO.

### Reconciliation and migration safety

- Added scoped discovery and validation of Civo private load-balancer
  addresses.
- Added an opt-in, one-time server-side-apply migration for service fields
  previously owned by other field managers.
- Declared the CloudNativePG additional-service update strategy required for
  repeatable reconciliation.
- Added offline tests for private-address selection, DNS publication,
  server-side-apply ownership migration, CoreDNS forwarding, ACME self-checks,
  and WireGuard gateway rules.

### Local development

- Added a Docker Compose environment for Aetheric Forge and Black Circuit
  development services.
- Added local Keycloak bootstrap, PostgreSQL and MongoDB initialization, and
  host NGINX configuration.

## Deployment model

The reference Civo environment uses the following traffic paths:

- Public application traffic enters through the public Civo ingress load
  balancer.
- Internal web traffic enters through the private Civo ingress load balancer.
- Private non-HTTP services use dedicated Civo load balancers and internal DNS
  records containing their private addresses.
- The Civo VPC reaches the home network through the WireGuard gateway.
- Internal DNS clients query Pi-hole on port 53. Pi-hole forwards the internal
  zone to BIND on port 5335.
- ExternalDNS and cert-manager send authenticated RFC2136 updates directly to
  BIND on port 5335.
- cert-manager also performs DNS-01 propagation checks directly against BIND
  to avoid resolver negative caching.

## Upgrade notes

### Existing Civo services

Existing clusters may have conflicting server-side-apply ownership for the
MongoDB load-balancer annotation or the CloudNativePG additional-Service list.
Run the following once after reviewing the desired service definitions:

```bash
./scripts/create.sh --platform-services --adopt-service-fields
```

Subsequent reconciliations should use the normal command without the adoption
flag:

```bash
./scripts/create.sh --platform-services
```

### WireGuard gateway

The gateway must forward IPv4 traffic and masquerade traffic leaving `wg0` for
the configured home CIDR. Existing gateways must receive the updated
`PostUp`/`PostDown` configuration; changing only the live firewall rule will not
survive a gateway restart.

### Internal DNS

The home DNS host must:

- Listen for ordinary resolver traffic on port 53
- Provide the authoritative RFC2136 endpoint on port 5335
- Permit TCP and UDP DNS traffic from the WireGuard tunnel
- Permit authenticated updates from the configured cert-manager and
  ExternalDNS TSIG keys

### MinIO identity policy

The Keycloak group used for MinIO administrators is `minio-admins`. Its MinIO
policy grants `admin:*`, `kms:*`, and `s3:*` permissions equivalent to the
built-in `consoleAdmin` policy.

## Compatibility and operational boundaries

- The fully exercised reference environment is the Civo `dev` overlay.
- Local k3s and AWS deployment assets remain in the repository but are not the
  reference path for this release.
- Internal services depend on the WireGuard route to the home DNS network.
- Civo private load-balancer addresses are discovered during deployment; the
  bootstrap scripts are not a continuous address-discovery controller.
- SOPS-encrypted manifests are intentionally tracked. Decryption keys and
  plaintext environment files must remain outside Git.

## Validation performed

The reference environment has been validated for:

- Public and private ingress routing
- Internal and external DNS publication
- WireGuard connectivity between the Civo VPC and home network
- RFC2136 updates from ExternalDNS and cert-manager
- Private ACME issuance and renewal
- Keycloak login to Argo CD and MinIO
- MinIO administrative access through the `minio-admins` group
- Private endpoints for RabbitMQ, PostgreSQL, MongoDB, Redis, and MinIO
- Repeatable service reconciliation after field-ownership adoption

## Known limitations

- Disaster-recovery and full clean-room bootstrap testing are not yet
  automated.
- Civo private service address discovery must be rerun after a load balancer is
  replaced.
- The repository does not yet provide continuous end-to-end monitoring for the
  WireGuard, DNS, and ACME dependency chain.
